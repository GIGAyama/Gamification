# Gamification — 小学校学習記録×ゲーミフィケーション

小学校のさまざまな学習活動を児童が主体的に楽しんで行えるようにするための、
Web アプリ「まなびクエスト」のリポジトリです。

児童は **1つのURL** を開くだけで、学習アプリで遊ぶ → きろくを送る → 経験値・レベル・バッジになる、
という流れがつながります。先生は **スプレッドシート1枚**（＝データベース）を持つだけで、
課題の出題・提出率の把握・所見の下書き・学期末PDFまでを同じ場所で扱えます。

### 児童ができること

| **けいけんち・レベル** | ログインボーナス、きろく、学習アプリの時間、連続きろく、自己ベスト更新などが経験値になり、レベルが上がる |
| **ミッション・バッジ** | デイリー／ウィークリー／クラス協力のミッション（初期16件）と、達成条件つきバッジ（初期26件） |
| **ガチャ・きせかえ** | 経験値でガチャを回してアバターアイテムを集め、着せ替える。重複は交換ポイントになる |
| **がんばりの可視化** | がんばりカレンダー・連続きろく日数・成長カード・じこベスト・まなびレーダー・むかしの自分 |
| **めあてと週次ふり返り** | 自分でめあてを立て、週の終わりにふり返って次のめあてにつなぐ |
| **仲間とのつながり** | クラス共同目標ゲージ、友だちへの応援スタンプ、各種ランキング、みんなの本だな・アバター |
| **先生からのかだい** | 届いた課題をカードで見て、そのままアプリ／きろくへ進み、やり切ったら「うけとる！」でごほうび |
| **低学年でも読める** | 児童画面の漢字に自動ふりがな、ヘッダーの「あ／あ／あ」で文字サイズを3段階 |

## 📁 構成

このリポジトリは、次の 2 つをセットで運用します。

| フォルダ | 内容 | 配置先 |
|---|---|---|
| **[`manabi-quest/`](./manabi-quest/)** | **まなびクエスト本体**。学習記録・ふり返り・ゲーミフィケーション・AI所見・PDF出力に加え、**先生が児童に出す「課題」と提出率の自動集計**、努力の成果を実感するための可視化（がんばりカレンダー・成長カード・じこベスト・めあて・週次ふり返り・応援スタンプ）と、GIGA山学習アプリ群の**共通学習ログ（study.v1）の収集サーバー**、**学習アプリを新しいタブでひらく「がくしゅうアプリ」**を内蔵 | Google Apps Script（スプレッドシートにバインド） |
| **[`manabi-portal/`](./manabi-portal/)** | **学習ポータル（PWA本体）**。まなびクエストを全画面表示しながら、**同じ画面から学習アプリのデータを送信**でき、下部ナビゲーションバーと「戻る」操作を提供します。児童にはこのURLを配付します | GitHub Pages（このリポジトリから公開） |
| `manifest.json` / `sw.js` / `icons/` | **PWA（インストール可能なアプリ）の定義**。アプリ名・アイコン・オフライン起動を担当します | GitHub Pages（リポジトリのルート） |
| [`tools/`](./tools/) | **自動テスト**。受信側 study.v1・課題の提出判定・経験値・分析・ポータルとの受け渡しを、スプレッドシートを触らずに手元で確かめます（`npm test`） | 手元で実行（配信しません） |
| [`scripts/`](./scripts/) | **品質ゲート**。構文・秘密情報・OAuthスコープ・`postMessage` の宛先などを機械的に検査します（`npm run check`） | 手元と CI で実行（配信しません） |

学習アプリの学習ログは `localStorage` にあり、同一オリジンのページからしか読めません。
そのため**ポータル（github.io）を親ページ、まなびクエストを iframe** にする構成にしています
（詳しくは [manabi-portal/README.md](./manabi-portal/README.md)）。

> 📖 **先生向けの使い方ガイドは [MANUAL.md](./MANUAL.md) にあります。**
> 専門用語を使わずに、配付URL・ホーム画面への追加手順・「うまくいかないとき」をまとめています。
> このリポジトリの現状診断は [AUDIT.md](./AUDIT.md) を参照してください。

## 🎮 学習アプリをひらく

まなびクエストのホームに **「がくしゅうアプリ」** があり、GIGA山の学習アプリ
（Qalc / 漢字タウン / けいさんカード / さんすうブロック / 100マス計算 / 九九カード /
どくしょ ちょきんばこ / Typa / かきかたマスター）を **アイコン・教科ラベル・ひとこと説明つきのタイル**からえらんで
**新しいタブ**でひらけます。タイルの絵は**各アプリが自分のリポジトリで用意しているPWAアイコン**を
そのまま読み込むので、児童がホーム画面に入れているアイコンとそろいます
（アプリ側で描きかえれば、まなびクエストは何もしなくても新しい絵になります）。

学習アプリはまなびクエストとは別のサイトにあり、同一オリジンでないと学習ログを読めないため、
**まなびクエストの中に埋め込むことはできません**。新しいタブでひらくかわりに
まなびクエストは開いたまま残るので、あそんだあと そのタブに帰って
「きろくを おくる」を押せば、そのまま経験値になります
（`あそぶ → もどる → おくる` が1か所でつながります）。

一覧の中身は [`manabi-quest/10_studylog.gs`](./manabi-quest/10_studylog.gs) の `STUDY_APP_LINKS`、
学年で使わないアプリは「初期設定」の `学習アプリリンク非表示` で外せます。

## 📋 課題を出す・提出率を見る

教員画面の **「課題・提出」** タブから、児童に課題を出せます。出せるのは2種類です。

| 種類 | 例 | 提出の判定 |
|---|---|---|
| **学習アプリ** | 「Qalcを10分」「100マス計算を3回」 | 学習ログ（study.v1）が届いた時点で**自動** |
| **きろく** | 「自主学習を1回書く」 | そのきろくが保存された時点で**自動** |

宛先は **クラス全員** でも **児童を選んで個別** でも出せます。先生が丸をつける作業はなく、
課題ごとの提出率と**未提出児童の名前**（押すとその児童の詳細へ）、**児童×課題のマトリクス**が
そのまま出ます。期限をすぎた未提出がたまった児童は、ダッシュボードの**声かけリスト**にも並びます。

児童の画面では、課題カードから**そのままアプリを新しいタブでひらく／きろくのフォームへ行く**ことができ、
やり切ると **「うけとる！」** でごほうびの経験値がもらえます。

> 提出は専用のシートに保存せず、`ログ` と `学習ログ` から毎回みちびいています。
> そのため、先生が目標値や期限をあとから直すと、提出の判定もその場で追いつきます。

くわしくは [manabi-quest/README.md の「課題と提出率」](./manabi-quest/README.md#課題と提出率) を参照してください。

## GitHub Pages で公開する

学習ポータルはこのリポジトリからそのまま公開できます。

1. GitHub の **Settings → Pages** を開く
2. **Source** を `Deploy from a branch`、**Branch** を `main` / `/ (root)` にして Save
3. 数分後、次のURLで公開されます

   | URL | 内容 |
   |---|---|
   | `https://gamification.giga-school.com/` | 入口ページ（ポータルへのリンク） |
   | `https://gamification.giga-school.com/manabi-portal/` | **学習ポータル（児童に配付するURL）** |

`manabi-quest/` は Apps Script へ貼り付けるためのソースで静的サイトとしては動かないため、
[`_config.yml`](./_config.yml) で配信対象から除外しています。

### ⚠️ 公開するときの手順（ファイルを直したら必ず）

`manabi-portal/` `index.html` `offline.html` `icons/` `manifest.json` のいずれかを直したら、
**[`sw.js`](./sw.js) の `VERSION` を必ず1つ上げてから push してください。**

```javascript
const VERSION = 'v4';   // → 'v5' のように上げる
```

Service Worker はキャッシュ名にこの版数を含めています。上げないと、
すでにアプリを入れている児童の端末では **前のファイルが出続けます**
（「直したのに変わらない」の原因のほとんどがこれです）。

上げると、児童の画面に「✨ あたらしいバージョンがあります」が出て、
タップすると `SKIP_WAITING` → 再読み込みで新しくなります。

> まなびクエスト本体（Apps Script）は毎回サーバーから読み込むため、この版数とは無関係です。
> 本体を直したときは **「デプロイを管理」→ 既存のデプロイを編集** で版だけ上げてください。
> **新規デプロイを作るとURLが変わり、児童のブックマークが切れます。**

### ⚠️ `manabi-quest/` を直したときは、Apps Script への貼り替えが要ります

GitHub と Apps Script は**自動で同期しません。** `manabi-quest/` の中を直しても、
Apps Script エディタに貼り直さないかぎり本番は古いままです。

1. Apps Script エディタを開き、変更したファイルの中身を**まるごと貼り替える**
2. **「デプロイを管理」→ 既存のデプロイを編集 → バージョンを「新バージョン」** にして更新
3. ポータルを開き直して、児童の画面が出ることを確かめる

貼り替えが済むまでの間は「新しいポータル ＋ 古い本体」の組み合わせになりますが、
**そのままでも動くように作ってあります**（本体は `APP_READY` で自分の対応状況を
名乗り、ポータルはそれを見て送信経路を選びます）。

## 📲 アプリとしてインストールする（PWA）

学習ポータルは **PWA** に対応しています。ブラウザで開いたあと、次の操作でホーム画面や
アプリ一覧に追加でき、以後はブラウザのアドレスバーなしの**全画面アプリ**として起動します。

| 端末・ブラウザ | 操作 |
|---|---|
| **Android / PC（Chrome・Edge）** | 画面下に浮かぶ案内バーの **「入れる」** ボタン、またはアドレスバーの **インストール** アイコン |
| **iPhone / iPad（Safari）** | 「共有」ボタン → **「ホーム画面に追加」**（案内バーには手順だけが出ます） |
| **Chromebook（Chrome）** | メニュー → **その他のツール → ショートカットを作成 / アプリをインストール** |

- 案内バーを ✕ で閉じたあとでも、**「📲 アプリとして入れる」** ボタンから入れられます。
  幅768px以上の画面（PC・タブレット横）では上部バーに、**どの端末でも「⚙️ せってい」の下部**に出ます
  （上部バーは幅768px未満では画面ごと出ないため、小さい端末では設定シートが入口です）
- ボタンは**インストールできない環境でも押せます**。Chrome の合図が来ていないとき
  （iPhone の Safari、Firefox、すでに入れてある端末）は、その端末での**入れかたの案内**が出ます
- 起動アイコン・スプラッシュ画面は [`icons/`](./icons/) の画像を使います
  （再生成する場合は [`icons/make_icons.py`](./icons/make_icons.py) を実行）
- 通信できないときは [`offline.html`](./offline.html) の案内が出ます
- **まなびクエスト本体（Google Apps Script）は毎回サーバーから読み込みます**。
  学習記録がキャッシュに残って古い内容が出ることはありません
- インストール後は、アイコンの長押し（右クリック）で **「きろくを おくる」ショートカット**が使えます
  （[`manifest.json`](./manifest.json) の `shortcuts`。`?action=send` 付きで開き、読み込み後に1回送信します）

> インストールは PWA の要件どおり **HTTPS** が必要です。GitHub Pages はHTTPSなのでそのまま使えます。
> ローカルの `file://` で開いた場合はインストールできません。

### ポータルが受け取るURLパラメータ

先生が設定を配るためのものです。**受け取った値は保存したうえで
`history.replaceState()` でURLから消す**ので、送信キーがブラウザの履歴に残りません
（[`manabi-portal/index.html`](./manabi-portal/index.html) の `applyUrlParams()`）。

| パラメータ | 意味 |
|---|---|
| `app` | まなびクエスト本体のWebアプリURL（**これだけで運用できます**） |
| `endpoint` | 学習ログ受信用のWebアプリURL（アクセス「全員」のデプロイを併用するときだけ） |
| `key` | 学習ログ送信キー（`endpoint` を使うときだけ） |
| `auto` | ページを開いたときの自動送信（**既定は有効**）。`auto=0` / `auto=off` で無効、それ以外の値・値なしで有効。「⚙️ せってい」のチェックボックスと同じ設定です |
| `action=send` | 自動送信を切っていても、読み込み後に1回だけ送る（ホーム画面ショートカット用） |

> ⚠️ `key` の付いたURLを児童に配らないでください。児童の端末では
> ポータルの **「⚙️ せってい」** から先生が入力します。

## 📱 画面と操作（スマートフォン・タブレット）

- **コンテンツ領域を最大化**: 小さい画面ではポータルの上部バーを出さず、画面のほぼ全部を
  まなびクエスト本体に使います。ノッチやホームバーは `env(safe-area-inset-*)` で避けます
- **いつも画面いっぱい**: 指2本でつまむ操作（ピンチ）でうっかり縮めると、アプリだけが端末の画面より
  小さくなって、まわりにすきまが出たままになります。`minimum-scale=1.0` で 100% より小さくできない
  ようにし、それが効かない端末むけに、縮んだことに気づいたら 100% に戻す処理も入れています
  （**拡大は今までどおりできます。止めているのは縮小だけです**）
- **下部ナビゲーションバー**: 「もどる」「おくる」「ばんごう」「せってい」。
  通知や設定はコンテンツの上に浮かせて表示するので、表示面積が減りません
- **戻る操作**: 次の3つはすべて「1つ前の階層へ戻る」に統一されています
  1. 下部バーの **「もどる」** をタップ
  2. **画面の左右どちらかの端から中央へスワイプ**
  3. ブラウザ／端末の戻る（Androidの戻るジェスチャー、iOSの端スワイプ、戻るボタン、Alt+←）
- **アプリが終了しません**: 戻る操作はポータルが履歴ガードで受け止めるため、
  戻ってページを離れる（＝アプリが閉じる）ことはありません。
  ジェスチャーとブラウザの戻るが同時に起きても、戻るのは1階層だけです

### 同一オリジンについて

学習ログ（`localStorage` の `study.records.v1`）を読めるのは、学習アプリと**同一オリジン**の
ページだけです。オリジンは **スキーム＋ホスト＋ポート** で決まり、**パスは関係しません**。
いまは各学習アプリが `<アプリ名>.giga-school.com` の別オリジンにあるため、
ポータルが自分の `localStorage` を読むだけでは足りません。各アプリに置いた
読み取り専用の受け渡し口（`records-export.html`）を**同一サイトの `iframe`**
で開いて取り寄せます（サブドメイン同士は同一サイトなのでストレージ分離の対象外）。

## 🔐 セキュリティ設計

### 信頼境界

**信用してよい入力は、サーバー側の `Session.getActiveUser().getEmail()` だけ**です。
`postMessage` の中身・`google.script.run` の引数・URLパラメータは、すべて改ざん可能として扱っています。

| 層 | 何を信じるか |
|---|---|
| ポータル（GitHub Pages） | **何も信じない**。表示と受け渡しだけを担当し、判定はしない |
| まなびクエスト（GAS） | ログイン中のメールアドレスのみ。ここから児童・教員を判定する |

児童の出席番号は、ポータルの手入力より **本体のログイン判定を優先**します。
共用端末で前の児童の番号が残っていても、ログインした児童の記録として保存されます。

### 個人情報の扱い

- **ポータルは氏名もメールアドレスも持ちません。** 自分で作るキーは
  `studySender.config.v1`（本体URL・受信用URL・送信キー・自動送信の可否）、
  `studySender.number.v1`（出席番号）、`studySender.installHint.v1`（案内バーを閉じたか）の3つだけです
- 送信するボディは `{ api, token, studentNumber, records }` です。
  **出席番号は送りますが、「誰のきろくか」の判定には使われません。**
  本体経由（推奨経路）ではサーバーが `Session.getActiveUser().getEmail()` から児童を特定し、
  出席番号は**それで見つからなかったときだけ**のフォールバックです
  （[`10_studylog.gs`](./manabi-quest/10_studylog.gs) の `receiveStudyLog_`）。
  送信キー `token` は本体経由では除いてから渡します
- 学習ログ `study.records.v1` は仕様どおり氏名・出席番号・メールを持ちません
- ポータルは `localStorage.clear()` を使いません。書き込むのは上の3つと、
  **`study.records.v1` から「送信ずみのレコードだけを取り除いて書き戻す」処理**（`removeRecords()`）だけです。
  他の学習アプリが作ったキーには一切触れません
- 学習ログに残す開始時刻の細かさは「初期設定」の `学習ログ時刻精度` で決まります。
  **標準は「時間帯」**で、`午前` / `午後` / `夕方以降` の3つにまるめて保存します
  （`分` にすると `HH:mm` まで残ります／`10_studylog.gs` の `studyTimeSlot_()`）

### 同一オリジン共有への配慮

旧配信元の `gigayama.github.io` は数十個の学習アプリが同じオリジンを共有していました。同居する配置に戻したときのため、
[`sw.js`](./sw.js) は `caches.keys()` を全削除せず、**`manabi-` で始まるキャッシュだけ**を掃除します。
全削除すると、他のアプリがオフラインで起動しなくなるためです。
Service Worker は `localStorage` に一切触れません。

### 秘密情報

- Gemini APIキーは `PropertiesService`（スクリプトプロパティ `GEMINI_API_KEY`）に置きます。**ソースに直書きしません**
- 学習ログ送信キーは、先生が「⚙️ せってい」で入力するかURLパラメータで渡し、
  **端末の `localStorage` にだけ**保存されます。リポジトリには含まれません。
  URLで渡した場合も、保存後すぐ `history.replaceState()` でURLから消します
- [`.gitignore`](./.gitignore) で `.clasp.json` `.env` の混入を止めています

### OAuth スコープについて

[`appsscript.json`](./manabi-quest/appsscript.json) が要求している 10 個のスコープと、
それぞれを何に使っているかの一覧です。

| スコープ | 使う機能 | 主な呼び出し |
|---|---|---|
| `auth/spreadsheets` | データベース（スプレッドシート）の読み書き | `SpreadsheetApp` 全般 |
| `auth/drive` | フォルダ指定・PDFの保存先解決・アーカイブの移動（**下記のとおり広すぎるため理由を明記**） | `DriveApp` |
| `auth/script.external_request` | AI所見・AIコーチ・道徳フィードバックの Gemini API 呼び出し | `07_ai.gs` の `UrlFetchApp.fetch` |
| `auth/script.send_mail` | 週次サマリーメールの送信（宛先は児童マスタの担任アドレス） | `09_ops.gs` の `MailApp.sendEmail` |
| `auth/script.scriptapp` | 週次サマリーメールの時間主導型トリガーの作成・削除 | `09_ops.gs` の `ScriptApp.newTrigger` ほか |
| `auth/userinfo.email` | ログイン中のアカウントの特定（児童／担任の判定、学習ログの持ち主の特定） | `Session.getActiveUser().getEmail()` |
| `auth/script.container.ui` | スプレッドシートの「🎒 まなびクエスト管理」メニューと確認ダイアログ | `SpreadsheetApp.getUi()` |
| `auth/classroom.announcements` | 道徳ノートのAIフィードバックを Classroom の個別お知らせとして投稿 | `07_ai.gs` の `Classroom.Courses.Announcements.create` |
| `auth/classroom.rosters.readonly` | 投稿先の児童を Classroom のプロフィールから解決 | `07_ai.gs` の `Classroom.UserProfiles.get` |
| `auth/classroom.profile.emails` | 同上（メールアドレスから Classroom のユーザーIDを引くため） | 同上 |

Classroom の3つは、**「初期設定」の `Google Classroom コースID` を空欄にしておけば一切呼ばれません**
（`07_ai.gs` はコースIDが入っているときだけ投稿します）。Classroom を使わない学校でも
認可の同意画面には出るため、この表で用途を示しています。

#### なぜ `auth/drive`（Drive全体）なのか

**最小権限の原則からは広すぎる**ため、理由をここに明記します。

| 使用箇所 | 呼び出し | なぜ `drive.file` では足りないか |
|---|---|---|
| `02_setup.gs` | `DriveApp.getFolderById(folderId)` | 先生が任意に指定したフォルダIDを開くため。`drive.file` はアプリが作った／開いたファイルにしか届かない |
| `08_pdf.gs` | `DriveApp.getFileById(ss.getId()).getParents()` | 学期末ポートフォリオPDFの保存先を、バインド元シートの親フォルダから解決するため |
| `09_ops.gs` | アーカイブ用スプレッドシートの `moveTo(folder)` | 同上 |

`https://mail.google.com/`（Gmail全体）と `auth/drive.readonly` は**要求していません**。
メール送信は `script.send_mail` に限定しています。

> 縮小するには、保存先フォルダを「バインド元シートと同じ場所」に固定して
> `getFolderById` をやめる必要があり、**GAS 本体の機能変更＋全先生の再認可**を伴います。
> 実運用中のPDF・アーカイブを壊すリスクがあるため、現時点では据え置いています。

### CSP を入れるときの手順

外部からの読み込みが無い [`index.html`](./index.html) と [`offline.html`](./offline.html) には、
すでに厳しい CSP を入れてあります（Chromium 実機でブロック0件を確認済み）。

[`manabi-portal/index.html`](./manabi-portal/index.html) には**まだ入れていません。**
iframe が `script.google.com` → `accounts.google.com` → `〇〇.googleusercontent.com` と
Google の中を移動し、その遷移先が端末・アカウントの状態で変わるためです。
書きちがえると「iframe がまっしろのまま、原因も出ない」状態になります。

入れるときは、**本番のGASデプロイにつないだ実機**で次の手順を踏んでください。

1. 未ログインの児童アカウントでポータルを開き、DevTools のコンソールを開いたままにする
2. 下のポリシーを `<head>` に入れる（`frame-src` は実際に遷移したドメインで補正する）

   ```html
   <meta http-equiv="Content-Security-Policy" content="
     default-src 'self';
     img-src 'self' data:;
     style-src 'self' 'unsafe-inline';
     script-src 'self' 'unsafe-inline';
     connect-src 'self' https://script.google.com https://script.googleusercontent.com;
     frame-src https://script.google.com https://accounts.google.com https://*.googleusercontent.com;
     manifest-src 'self'; worker-src 'self';
     object-src 'none'; base-uri 'self'; form-action 'none'">
   ```

3. **ログイン → 表示 → きろく送信 → 設定の接続テスト**まで通し、
   コンソールに `Refused to` が**1件も出ない**ことを確認する
4. 1件でも出たら**入れずに戻す**。授業中に原因が見えない壊れ方をするほうが害が大きい

> `frame-ancestors` は `<meta>` では無視されます（HTTPヘッダー専用）。GitHub Pages では設定できないため入れていません。

push と Pull Request のたびに、[`.github/workflows/quality.yml`](./.github/workflows/quality.yml) が
次の 2 つを自動で回します。手元でも同じものを走らせられます。

### `npm run check` が見ているもの

検査の本体 [`scripts/lib/project-quality.mjs`](./scripts/lib/project-quality.mjs) は
**`SchoolPlan_Editor` の正本を1バイトも変えずにコピーした**ものです。
正本が新しくなったら、そのまま上書きコピーしてください。

| 検査 | 内容 |
|---|---|
| `REQUIRED_FILE_MISSING` | 必要なファイルがそろっているか |
| `MERGE_CONFLICT_MARKER` | `<<<<<<<` などの消し忘れ |
| `SECRET_CANDIDATE` | APIキー・トークン・秘密鍵らしき文字列 |
| `HTML_SCRIPT_SYNTAX` / `GAS_SYNTAX` | ファイルごとの構文 |
| `GAS_GLOBAL_SYNTAX` | 全 `.gs` をつないだときの構文（トップレベル名の重複） |
| `HTML_INCLUDE_MISSING` / `HTML_ASSEMBLY_FAILED` | `include('...')` の宛先が無い／展開できない |
| `ASSEMBLED_APP_SYNTAX` | `include()` を展開したあとの構文 |
| `MANIFEST_INVALID` / `FORBIDDEN_OAUTH_SCOPE` | `appsscript.json` と OAuth スコープ |
| `WILDCARD_POSTMESSAGE` | `postMessage(..., '*')` が残っていないか |
| `XFRAME_ALLOWALL` | `XFrameOptionsMode.ALLOWALL` の使用 |
| `LARGE_FILE_LINES` / `LARGE_FILE_BYTES` | 5,000行・400KB を超えたら警告 |

このリポジトリは C+型で中身が 2 つに分かれているため、
[`scripts/check-project.mjs`](./scripts/check-project.mjs) が検査を **2 回**まわします。
設定はそれぞれの場所に置いています。

| 場所 | 設定ファイル | 対象 |
|---|---|---|
| リポジトリ直下 | [`quality.config.json`](./quality.config.json) | GitHub Pages 側（児童が開くページ） |
| `manabi-quest/` | [`manabi-quest/quality.config.json`](./manabi-quest/quality.config.json) | Apps Script 側 |

### 明示的に許可している例外

**検査を緩めるのではなく、理由を書いて明示的に許可します。** いまある例外は 2 つだけです。

| 例外 | 場所 | 理由 |
|---|---|---|
| `XFRAME_ALLOWALL` | `03_main.gs` | ポータルの iframe に本体を表示するために必要。これが無いと C+型の構成が成り立ちません |
| `auth/drive` を禁止リストから外す | `manabi-quest/quality.config.json` | 上の「OAuth スコープについて」の理由。判断の記録として設定ファイル内にも書いてあります |

`WILDCARD_POSTMESSAGE` の例外は **ゼロ**です。宛先のオリジンは必ず 1 つに決めています。

> ⚠️ `ALLOWALL` は「**どのサイトからでも iframe に埋め込める**」という意味で、
> 埋め込み元を絞る設定ではありません（GAS には特定オリジンだけを許す設定がありません）。
> 絞っているのは**本体からポータルへ返す `postMessage` の宛先**のほうで、
> `sanitizePortalOrigin_()` が URLパラメータ `portalOrigin` を
> `https://〇〇.github.io` の形にだけ通し、合わなければ空にして既定値を使います。
> 宛先を偽られても、ブラウザは宛先オリジンが実際に一致するときしかメッセージを届けないため、
> 別のサイトに埋め込まれても中身は読み取られません。
> 加えて、サーバー側の判定はすべて `Session.getActiveUser().getEmail()` に依っているので、
> 埋め込み元が誰であっても他人の記録は読めません。

### 組織アカウントで、デプロイの「アクセスできるユーザー」に **全員** が出ないとき

学校（Google Workspace）のポリシーによっては **組織内** しか選べません。**そのままで使えます。**

学習ログは、ポータルが**画面に表示しているまなびクエスト（＝ログイン済みのWebアプリ）ごしに**送ります。
ログイン済みのセッションの中から `google.script.run` で保存するため、CORS も匿名アクセスも不要で、
デプロイは **組織内** のままでかまいません。

- 作るデプロイは**本体の1つだけ**でOK（アクセス: 組織内 / 実行ユーザー: 自分）
- ポータルに渡すのは **`?app=<本体のWebアプリURL>`** だけ。`endpoint` と `key` は空欄のままでOK
- 管理者に外部共有の許可を依頼する必要はありません

詳しくは [`manabi-quest/README.md`](./manabi-quest/README.md#3-webアプリとして公開) を参照してください。
