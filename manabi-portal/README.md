# 🎒 まなびクエスト 学習ポータル（manabi-portal）

**「まなびクエスト」と「学習データの送信」をひとつの画面にまとめた入口ページ**です。
gigayama.github.io（学習アプリと同一オリジン）で公開し、児童はここから毎日アプリを開きます。

```
┌─ https://gigayama.github.io/Gamification/manabi-portal/ ───┐
│                                                            │
│                                                            │
│        まなびクエスト（GAS Webアプリ）を全画面で表示          │ ← ホーム／きろく／クエスト／ひろば
│        アプリ内の「きろくを おくる」ボタンも使えます           │
│        ←  画面の左右の端からスワイプで「もどる」  →           │
│                                                            │
├────────────────────────────────────────────────────────────┤
│   ◀ もどる    📨 おくる(3)    🔢 12      ⚙️ せってい          │ ← 下部ナビゲーションバー
└────────────────────────────────────────────────────────────┘
```

小さい画面では上部バーを出さず、**画面のほぼ全部をまなびクエスト本体**に使います
（PCやタブレット横向きでは、上部にブランド行と件数表示が出ます）。

## なぜ「ポータルが親・まなびクエストが iframe」なのか

学習アプリの学習ログは `localStorage`（`study.records.v1`）に保存されており、
**同一オリジンのページからしか読めません**。
さらに近年のブラウザは第三者 iframe のストレージをトップレベルサイトごとに分離するため、
**まなびクエスト（script.google.com）の中に github.io を iframe で置いても、学習ログは読めません**。

読み出せるのは「gigayama.github.io がトップレベルのとき」だけなので、

- **親ページ（このポータル）** … 学習ログの読み出しと送信を担当
- **iframe（まなびクエスト）** … 経験値・ミッション・ランキングの表示を担当

という構成にしています。iframe の中のまなびクエストからは `postMessage` で親に送信を依頼できるので、
児童から見れば「**まなびクエストの中に送信ボタンがある**」ように使えます。

## 児童から見た動き

1. ポータルを開く（Classroom などにこのURLを貼っておく）／ホーム画面のアイコンから起動する
2. **出席番号は入力しません**。まなびクエストにログインしているアカウントから自動で決まります
   （手で変えたいときだけ下部バーの「🔢 ばんごう」）
3. たまっている学習ログが**自動で送信**されます（設定でOFFにできます）
   手動で送るときは、下部バーの「📨 おくる」か、まなびクエスト内の「きろくを おくる」ボタン
4. 受理されると、まなびクエストの画面がそのまま更新され、獲得EXP・ボーナス・レベルアップが表示されます

## 操作（下部ナビゲーションバーと戻る）

| ボタン | はたらき |
|---|---|
| ◀ **もどる** | 1つ前の階層へ戻ります（開いているシートやダイアログがあれば先に閉じます） |
| 📨 **おくる** | たまっている学習ログを送ります。件数がバッジで出ます |
| 🔢 **ばんごう** | 出席番号。ふだんはログインから自動で入るので、直したいときだけ使います |
| ⚙️ **せってい** | 先生用の設定（本体URL・受信用URL・送信キー・自動送信）と、インストール方法 |

「戻る」は次の3つが同じ動きになります。**戻る操作でアプリが終了することはありません**。

1. 下部バーの「もどる」をタップ
2. 画面の左右どちらかの端から中央へスワイプ
3. ブラウザ／端末の戻る（Androidの戻るジェスチャー、iOSの端スワイプ、戻るボタン、Alt+←）

画面の階層（タブ・入力フォーム・ダイアログ）を持っているのは iframe の中のまなびクエストです。
ポータルは「戻ってほしい」という合図（`NAV_BACK`）を送るだけで、どこへ戻るかはアプリ側が決めます。
アプリは階層が変わるたび `NAV_STATE` を返し、ポータルは「もどる」の有効／無効をそれに合わせます。

## PWA（アプリとしてインストール）

このページは PWA として動きます。設定は [`../manifest.json`](../manifest.json)、
オフライン対応は [`../sw.js`](../sw.js) にあります。インストール手順は
[リポジトリの README](../README.md#-アプリとしてインストールするpwa) を参照してください。

Service Worker のスコープは `/Gamification/` だけなので、同じ `gigayama.github.io` にある
**他の学習アプリ（別リポジトリ＝別パス）には影響しません**。
また、まなびクエスト本体（`script.google.com`）は別オリジンなのでキャッシュせず、毎回サーバーから取得します。

## 配置場所

**学習アプリと同一オリジン**（`https://gigayama.github.io`）である必要があります。
オリジンはスキーム＋ホスト＋ポートで決まり**パスは関係しない**ので、
このリポジトリを GitHub Pages で公開するだけで条件を満たします。

```
https://gigayama.github.io/Gamification/manabi-portal/
```

公開手順はリポジトリの [README](../README.md#github-pages-で公開する) を参照してください。

## セットアップ手順

### 1. まなびクエスト側（GAS）

1. `manabi-quest/` の最新スクリプトを反映し、メニュー「① 初期セットアップ」を再実行
2. 「初期設定」シートを設定し、メニューの「🔄 設定キャッシュをクリア」を実行
   - `学習ポータルURL` … `https://gigayama.github.io/Gamification/manabi-portal/`
     （Webアプリを直接開いた児童に、ポータルへの導線を出すために使います）
   - `学習ログ送信キー` … 合言葉（例: `sakura-3nen`）。**匿名POSTを使うときだけ必要**で、
     空欄のままでかまいません（本体経由の送信はキーなしで動きます）
3. **デプロイは本体の1つだけで足ります**（実行ユーザー: **自分**）

   | 用途 | アクセスできるユーザー | 必須 | ポータルでの設定名 |
   |---|---|---|---|
   | 本体（iframe に表示するアプリ。送信もこの画面ごしに行う） | **組織内の全員** | ✅ | `app` |
   | 学習ログの受信（匿名POSTの受け口。予備の経路） | **全員** | 任意 | `endpoint` |

### 学習ログの送り方（2つの経路）

| 経路 | しくみ | 必要なデプロイ |
|---|---|---|
| **① 本体経由（既定・推奨）** | ポータルが iframe のまなびクエストへ記録を渡し、**ログイン済みのその画面**が `google.script.run` でサーバーに保存する | 本体（**組織内**）だけ |
| **② 匿名POST（任意）** | ポータルから受信用URLへ直接 `fetch` する。`fetch` は Google のログイン情報を送れないため匿名アクセスが必要 | 受信用（**全員**） |

ポータルはまず①を試し、届かなかったときだけ②へ切り替えます。

> **組織アカウントで「アクセスできるユーザー: 全員」を選べないとき**
> それでも大丈夫です。①の本体経由はデプロイが **組織内** のままで動きます。
> ポータルの設定は **`app`（本体URL）だけ**でよく、`endpoint` と `key` は空欄のままにしてください。
> 管理者に外部共有の許可を依頼する必要はありません。

### 2. ポータルの設定

次の形式のURLを一度開くと、設定が端末に保存されます（以後はパラメータ不要）。

```
# 本体経由だけで運用する（組織アカウントで「全員」を選べないときはこちら）
https://gigayama.github.io/Gamification/manabi-portal/?app=<本体のWebアプリURL>

# 匿名POSTも併用する
https://gigayama.github.io/Gamification/manabi-portal/?app=<本体のWebアプリURL>&endpoint=<受信用のWebアプリURL>&key=<学習ログ送信キー>
```

- 自動送信を止めたいときは `&auto=0` を付けます
- ページ内の「⚙️ せってい（先生用）」からも設定・接続テストができます
- 設定はブラウザごとに保存されるため、児童機ごとに一度この URL を開く必要があります
  （Classroom に配付する／ブラウザのホームページに設定する 等）

## iframe が表示できないとき

サードパーティ Cookie を強くブロックしている環境では、iframe 内でのGoogleログインが通らず
まなびクエストが表示できないことがあります。

- **何も読み込めなかったとき** … **「まなびクエストを 新しいタブでひらく」** ボタンに切り替えます
- **読み込めているが応答がないとき**（Googleのログイン画面が出ている等） … 画面は覆わず、
  「新しいタブでひらく」案内だけを下部に浮かべます（覆うとログインの続きができなくなるため）

どちらの場合も**ポータルの画面（下部バーの「📨 おくる」）はそのまま使えます**が、
送信の経路は次のようになります。

- **受信用デプロイ（アクセス: 全員）を設定してある** … そちらへ直接POSTするので、そのまま送信できます
- **本体経由だけの設定** … 送信には本体の画面が必要です。「新しいタブでひらく」で
  一度ログインを済ませてからポータルに戻ると、iframe が表示できるようになり送信できます

## フレーム構成に関する注意（実装者向け）

GAS の Webアプリは、`script.google.com` のページの中でさらに `googleusercontent.com` の
iframe を作り、その中でユーザーコードを動かします。ポータルに埋め込むと **3階層** になります。

```
ポータル（gigayama.github.io）… window.top
  └ script.google.com（GASのラッパー）… iframe.contentWindow
      └ googleusercontent.com（まなびクエストのコード）… postMessage の送り主
```

そのため `postMessage` は次のように扱う必要があります。

- まなびクエスト → ポータル: 宛先は `window.parent`（＝ラッパー）ではなく **`window.top`**
- ポータル → まなびクエスト: 宛先は `iframe.contentWindow`（＝ラッパー）ではなく
  **受信したメッセージの `event.source`**
- 送信元の確認: 「iframe そのものか」ではなく **`event.source.top === window`**
  （このページの中のどこかのフレームから来たか）で判定します

## セキュリティ・プライバシー

- 匿名の受信エンドポイント（`doPost`）は「学習ログ送信キー」が一致する POST だけを受け付けます
- 本体経由（`receiveStudyLogFromPortal`）は**Webアプリのアクセス権そのもの**が認証です。
  呼べるのは学校ドメインでログインし、児童マスタに登録されているアカウントだけなので、
  送信キーの照合は行いません（キーは匿名POST専用です）
- `postMessage` は双方向とも送信元を検証しています
  - ポータル → まなびクエスト: 送信先を GAS のユーザーコンテンツ オリジンに限定
  - まなびクエスト → ポータル: `*.github.io` かつ `window.top` からのメッセージのみ受理
  - ポータル側は「GASのオリジン」かつ「このページの中のフレーム」からのみ受理
- `postMessage` でやりとりするのは「未送信件数・出席番号・送信結果（獲得EXPなど）」と、
  本体経由で送るときの**学習ログそのもの**（`RELAY_POST`）です。
  学習ログの宛先は検証済みの GAS オリジンに限定しているため、他サイトには渡りません
- 児童の識別は経路によって変わります。学習アプリ層が匿名なのはどちらも同じです（仕様 §0-2）
  - **本体経由** … まなびクエストにログインしているアカウント（サーバー側で判定。手入力より確実）
  - **匿名POST** … このページが付与する出席番号
- 学習開始時刻は既定で「日付＋時間帯（午前/午後/夕方以降）」に丸めて保存されます（仕様 §4.1）
- まなびクエスト側の `doGet` は iframe 表示のため `XFrameOptionsMode.ALLOWALL` を指定しています。
  他サイトからも枠に入れられる状態になるため、児童に配るURLはポータルに統一してください
- 送信キーはクラス運用のいたずら防止が目的で、機密情報を守るためのものではありません
